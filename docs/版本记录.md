## 树洞 v1.1 — 2026-09-23

对比基线：`树洞v1.0`（2026-08-19）

这一版做的是三件事：**把"有表无实现"的治理能力真正跑起来**、**把空壳的数据权限落地**、**C 端全站视觉与布局重做**。

### 一、内容治理闭环（后端从 0 到可用）

| 能力 | 实现 | 说明 |
|---|---|---|
| 敏感词 | `SensitiveWordService` | Trie(DFA) 前缀树 + 内存缓存；L1 直接拦截 / L2 转人工审核；管理端改词后热刷新立即生效 |
| 禁言 / 封号 | `ThUserGuard` | 登录查封号、发帖评论点赞查禁言；违规计分 + 阈值自动处罚（默认 5 分禁言 3 天、10 分封号 7 天，后台可调）；所有处罚写 `th_user_log` 留痕 |
| 频次限额 | `ThRateLimiter` | 基于 Redis 的自然日计数，`max_post_per_day` / `max_comment_per_day` 真实生效 |
| 举报闭环 | `ThReportService` | 举报成立 → 内容下架 + 作者计违规 + 自动处罚 + 通知举报人；驳回也会告知——举报不再是黑洞 |

新增表：`th_sensitive_word`、`th_collect`（`sql/migration_v1.1.0.sql`）

### 二、数据权限：从"纯装饰字段"到真正生效（8 级分级）

```
1 全部数据                     5 本部门及以下(限 N 级)
2 本集团及以下                 6 本部门
3 本公司及以下                 7 自定义部门
4 本部门及以下                 8 仅本人
```

- `sql/migration_v1.2.0.sql`：新建 `sys_role_dept`、`sys_dept.dept_level`（含回填）、`sys_role.data_scope_level`
- 登录期预计算可见部门集合（`LoginUser.deptIds` / `deptTreeIds`），避免每条 SQL 递归组织树
- MyBatis-Plus `DataPermissionInterceptor` + `MultiDataPermissionHandler` 对 `sys_user` / `sys_dept` **自动追加数据范围条件**
- 历史 5 级数据**降序**重映射（5→8、4→7、3→6、2→4，顺序错会互相覆盖）

### 三、C 端全站改版：Deep Hollow 深空设计语言

- 深空底 `#06060D` + 玻璃拟态面板 + 单一强调色极光青 `#5FE0BD`（紫仅用于背景光晕）
- 字体：正文 Noto Sans SC｜诗意短句 Fraunces 斜体｜数据与标签 JetBrains Mono
- 背景：AI 生成极光树图 + 星云 3 团 + 银河带 + 晨光色彩带；深色星空为远/中/近三层 + 流星 + 滚动视差
- **全站移除 emoji 图标**，改为 28 个统一线性 SVG（`IconSprite` + `AppIcon`）
- 布局采用 **「App 式」**：宽屏左侧固定导航（含带帖子数的分类）+ 内容列 + 右栏（公告手风琴 / 回声 / 数据 / 公约）
- 按钮 5 层微交互：磁吸 + 聚光跟随 + 涟漪 + 扫光与箭头位移 + 按下回弹（事件委托安装，任何 `.dh-btn` 自动生效）
- 深色 / 浅色主题切换（默认深色，`localStorage` 持久化，同步 `html[data-theme]` 给 Element Plus）

### 四、新增功能（C 端）

通知中心、搜索、我的收藏、删帖 / 删评论、账号设置（含改密码）、他人主页、发帖审核开关、公告手风琴、
分类筛选写 URL（可分享 / 可后退）、触底自动加载、回到顶部、`/` 键聚焦搜索、置顶帖抽成精选卡。

### 五、这一版修掉的真缺陷

| 级别 | 缺陷 | 说明 |
|---|---|---|
| 🔴 | 点赞功能 100% 失败 | `th_like` 缺 `update_time` 列，而实体继承 `BaseEntity` 必带该列（建表脚本遗漏） |
| 🔴 | 举报闭环是死代码 | 管理端控制器自己重写了旧逻辑，绕过 Service，下架/计分/通知全没跑 |
| 🔴 | 数据权限把组织树打散 | 父节点被过滤后前端建树整体丢弃 → 改用「可见部门 + 祖先」集合，且不放大用户可见范围 |
| 🟠 | `GET /api/user/{id}/roles` 越权读 | 任意登录用户可查任意用户角色，已补权限码 |
| 🟠 | `/api/auth/**` 整段放行 | 收敛为 `captcha` / `login` / `refresh` 精确白名单 |
| 🟠 | 改密后旧 Token 仍有效 | 鉴权只认黑名单，删缓存无效 → 改为拉黑吊销 |
| 🟠 | 未登录点赞会把人登出 | 接口 401 → 拦截器登出并弹回登录页；已加登录前置引导 |
| 🟠 | 非数字路由 id 打成 500 | `/post/abc` → `Number()` 得 NaN → `GET /api/th/post/NaN`；已加参数守卫与友好空态 |
| 🟠 | 封号到期后仍无法登录 | 设置天数却把 `status` 置 0，到期不会恢复 |
| 🟡 | 登录页被外壳网格挤成半幅 | 布局 3 的两列网格在访客页留下 236px「空洞列」，整屏分屏塌成半幅 |
| 🟡 | `th_category.post_count` 从未被维护 | 分类数字冻结（16 条心事显示「全部 7」）→ 改为实时 GROUP BY 聚合 |
| 🟡 | 4 个单测基线即失败 | 继承来的 `baseMapper` 无法被 Mockito 注入，"有测试"是假象 |
| 🟡 | 移动端顶栏横向溢出 39px | 窄屏把主题/设置/退出收进「更多」下拉 |

## 已知遗留（下一版候选）

1. **写操作未按数据范围校验** —— `DataPermissionInterceptor` 只改写 SELECT，UPDATE/DELETE 目前靠权限码兜底
2. **Token 吊销用 `keys()` 全量扫描**，量大时应改为 `user:{id}:tokens` 集合
3. **th-admin 权限码仍是粗粒度 `admin`**，未按模块拆细
4. **管理端 UI 未统一**（有意为之，待单独立项）
5. **`scripts/browser_e2e.cjs` 待按新 UI 重写** —— 选择器基于改版前 UI，其中覆盖管理端的部分仍是唯一资产，暂留本地不纳入版本管理
6. **树洞前端没有 `tsconfig.json`** —— `vue-tsc` 跑不起来，`npm run build` 只做剥离不做类型检查，目前靠浏览器断言兜底
7. 登录页浅色主题下左侧引语（白字）对比度偏低
