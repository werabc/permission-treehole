# 权限管理系统（管理端 RBAC）审查报告

> 审查对象：`permission-admin`（Spring Boot 3.2 多模块）+ `permission-ui`（Vue3 管理端）
> 审查时间：2026-09-22 | 基线：`b3a51af` + 本次 A/B 升级提交（d357d9d / 7a98dba / af32247）
> 结论摘要：**权限校验骨架完整、认证链路扎实，但"数据权限"整条线未落地**，另有 3 处鉴权缺口与 4 个失效单测。

---

## 一、模型与实现现状

```
sys_user ──(sys_user_role)── sys_role ──(sys_role_menu)── sys_menu(目录/菜单/按钮)
    │                            │
  sys_dept(树)                data_scope: 1全部 2本部门及以下 3本部门 4自定义 5仅本人
```

**权限装配路径**（`UserDetailsServiceImpl.loadUserByUsername`）：
1. 查用户 → 查用户角色 → 角色码进 `roles`
2. 查角色菜单 → 菜单 `permission` 字段进 `permissions`
3. 计算 `dataScope`（取所有角色中最宽的值）→ 装入 `LoginUser`
4. `JwtAuthenticationFilter` 解析 Token → 注入 SecurityContext → `@PreAuthorize` 生效
5. 前端登录后调 `userMenus` 拉菜单树 → 动态注册路由（`permission.ts` componentMap 映射组件）

## 二、问题清单（按严重度）

### 🔴 P0-1 数据权限（data_scope）完全未落地 —— 最严重

**证据链**：
- `SysRole.dataScope` 字段存在、`DataScope` 枚举存在、管理端角色页也能设置
- `UserDetailsServiceImpl` 计算了它并塞进 `LoginUser`，**代码里甚至自带注释**：
  > `// deptIds remains empty for now: CUSTOM scope filtering not fully implemented`
- 全局检索 `dataScope`：**没有任何查询、任一 mapper XML、任一 MyBatis 拦截器使用它**
- `sys_role_dept` 表**根本不存在**（`create_tables.sql` / `init.sql` 都没有），所以"自定义数据范围"连存储都没有

**后果**：数据权限是个**纯装饰字段**。只要用户拥有 `xxx:list` 权限，就能查到**全公司**的数据，与角色的数据范围设置（本部门/仅本人）毫无关系。`/api/user/export` 同样导出全量用户。

**修复方案**（建议按顺序）：
1. 新建 `sys_role_dept` 表 + 角色页"自定义数据范围"选择部门
2. 写一个 MyBatis-Plus 拦截器 / 或统一在 Service 层拼条件：
   - `1 全部` → 不加条件
   - `2 本部门及以下` → `dept_id IN (SELECT id FROM sys_dept WHERE FIND_IN_SET(#{deptId}, ancestors) OR id = #{deptId})`
   - `3 本部门` → `dept_id = #{deptId}`
   - `4 自定义` → `dept_id IN (role_dept 配置)`
   - `5 仅本人` → `create_by = #{username}`（或 `user_id`）
3. 推荐用 `@DataScope` 注解 + AOP 注入 SQL 片段，避免每个查询手写

### 🟠 P1-2 接口鉴权覆盖不均（1 处真实越权读，其余为自服务端点）

逐端点核对结果：

| 端点 | 位置 | 判定 |
|------|------|------|
| `PUT /api/user/update-password` | `UserController:98` | ✅ 安全 —— 取 `loginUser.getUserId()`，只能改自己密码，属自服务，无需权限码 |
| `PUT /api/user/profile` | `UserController:121` | ✅ 同上，自服务 |
| `GET /api/user/{id}/roles` | `UserController:115` | ⚠️ **越权读** —— 无任何校验，任意登录用户可查询**任意用户**的角色 ID 列表，可据此探测高权限账户，为提权攻击做侦察 |

同类（仅登录即可访问的只读端点）：`MenuController`（7 端点 / 5 鉴权）、`RoleController`（9/7）、`DeptController`（6/5）、`OnlineUserController`（3/2）。**建议**：给 `GET /{id}/roles` 补 `@PreAuthorize("hasAnyAuthority('system:user:query','admin')")`，其余只读端点统一补齐权限码，避免"靠业务层自觉"。

---

### 🟠 P1-3 `/api/auth/**` 整体放行属于结构性隐患

`SecurityConfig` 中 `.requestMatchers("/api/auth/**").permitAll()`，覆盖 `user-info` / `logout` / `refresh`。
当前实现靠 `@AuthenticationPrincipal` + 手工判空兜底，**没有实际漏洞**；但这是"路径级白名单"而非"端点级白名单"——日后任何人往 `/api/auth/**` 下加管理端点（例如重置密码、改配置），会直接公网可达。

**建议**：收敛为精确端点白名单（`/api/auth/login`、`/api/auth/refresh`、`/api/auth/captcha` 放行，其余 authenticated）。

---

### 🟠 P1-4 按钮级权限前端只做了 4 个页面

`v-permission` 指令存在，但仅用于 `system/user`、`system/role`、`system/menu`、`system/dept`。
**树洞管理 11 个页面（th-admin/*）完全没有按钮级控制**，且其菜单 `permission` 字段统一写死为 `'admin'`（见 `init.sql` 440-446 行）—— 也就是说**树洞管理只有一个粗粒度开关**：要么整块可见，要么全不可见，做不到"能给审核员看内容但不能改站点配置"。

**建议**：给 th-admin 菜单拆细权限码（`admin:th:post`、`admin:th:user`、`admin:th:settings` …），后端 `@PreAuthorize` 同步替换（当前是 `hasAnyAuthority('admin')`），前端补 `v-permission`。

---

### 🟡 P2-5 单测基线是坏的（4 个用例失败）

`SysUserServiceImplTest` 4 个用例 **2 失败 2 报错**，全部是同一个原因：

```
NullPointerException: ... because "this.baseMapper" is null
  at SysUserServiceImpl.existsByUsername(SysUserServiceImpl.java:464)
```

`SysUserServiceImpl extends ServiceImpl`，代码走的是**继承来的 `baseMapper`**，而 Mockito 的 `@InjectMocks` 只能注入构造器/字段声明的依赖，注不进父类字段 → 这几个测试从写下那天起就没真正跑通过（已确认非本次改动引入）。

**影响**：项目"有测试"是假象，CI 若跑测试会红，于是大概率没人跑 → 等于没有回归网。

**修复**：用 `ReflectionTestUtils.setField(service, "baseMapper", userMapper)` 或改用 `@Spy` + 手工构造。

| 项 | 说明 | 建议 |

## 三、做得好的地方（避免只挑毛病）

- **认证链路扎实**：图形验证码**强制校验不可绕过**、登录 IP 限流、连续失败锁定、BCrypt 存储、Token 黑名单登出、Refresh Token 独立签发
- **权限装配干净**：`permissions` 直接来自菜单表的权限码，无硬编码角色判断（除树洞管理那个粗粒度 `admin`）
- **动态路由**：菜单树驱动前端路由注册，`componentMap` 显式白名单映射，未注册路径落 404，不存在"猜路径进入页面"
- **脱敏到位**：`getUserById` / `page` / 导出 都显式清空或排除密码字段；管理端用户详情不返回密码
- **审计闭环**：`@OperationLog` + AOP 记录模块/操作/耗时；本次升级又给处罚动作补了 `th_user_log` 留痕
- **防自删兜底**：删除角色前校验"是否已分配给用户"

## 五、本次升级顺带修掉的相关问题

- `ThUserAdminController` 封号：原实现 `days > 0` 也置 `status = 0`，导致**封号到期后仍无法登录**（`status` 永久为 0）；现已改为只设 `banUntil`，到期自动恢复
