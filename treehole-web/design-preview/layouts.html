按钮动效 · 5 个叠加的小动作

把鼠标移到按钮上、按住不放，感受这几层。右上角「动效 关」可以对比静态版。

① 磁吸 Magnetic —— 按钮被光标"吸"过去，文字跟得更慢一点，形成层次
位移系数 0.2（按钮）/ 0.08（文字）；移出时用 cubic-bezier(.34,1.56,.64,1) 回弹，带一点过冲。
② 聚光跟随 Spotlight —— 一团柔光跟着光标在按钮表面移动
用 radial-gradient + CSS 变量 --mx/--my，只在 hover 时显现，不额外增加 DOM。
③ 涟漪 Ripple —— 从按下那一点荡开一圈（点一下试试）
按下时创建一个 span，660ms 后自动移除；不堆积节点。
④ 悬浮扫光 Sweep + 箭头位移
一道斜向高光 0.62s 掠过按钮；箭头再向右推 4px。
⑤ 按下回弹 Press —— 按住时缩到 0.955，松开弹回
缩放走 --ps 变量，和磁吸的位移合成同一个 transform，不打架。
性能与可访问性：全部只改 transform / opacity（GPU 合成，不触发重排），60fps 无压力； 触摸设备不启用磁吸（没有 hover 概念）；prefers-reduced-motion 下自动全部关闭。

四套布局怎么选

同一份内容、同一套视觉，只换排布。顶部切换可以来回对比。

布局排布适合代价
1 剧院式
CENTERED		 830px 窄中栏一路到底，无侧栏，Hero 居中 最像"树洞"——安静、私密、专注，适合只看内容不找功能 桌面两侧留白大；公告/分类只能压在正文上方，弱化
2 瀑布式
MASONRY		 满宽；Hero 左 + 精选右；公告/回声/数据三栏条；帖子双列 浏览效率最高，一屏能看到最多的心事，像豆瓣/小红书 双列会打断"一条条往下读"的节奏；短帖旁边留空
3 App 式
SHELL		 左侧固定导航（广场/发布/消息/我的 + 分类）+ 中栏单列 + 右栏模块 功能长起来之后最好用；有"产品感"，分类随手可切 三栏在 1366 以下会挤；左侧导航对纯浏览用户是多余的一层
4 Bento
MAGAZINE		 Hero 左 + 精选右；下方 4 格宫格（公告 2×2 / 回声 / 数据 / 公约）；正文回到 840 居中 最好看、最有"设计感"；信息主次一眼分明，适合做首屏展示 宫格占屏高，首屏看不到帖子（要滑一下）；维护成本略高

我的建议

想要"一眼就记住"的观感 → 4 Bento；想要"最好读、最像树洞" → 1 剧院式； 想要"能看很多、以后还要加功能" → 3 App 式；想要"效率优先、一眼扫完" → 2 瀑布式。
如果让我只推一个：1 剧院式 + 把公告做成正文上方的一条细横幅——最贴题、最不容易出错，移动端也和现在完全一致（本来就是单列）。

按钮动效

5 个动作会作为全局基础件落到 main.css（磁吸 / 聚光跟随 / 涟漪 / 扫光+箭头 / 按下回弹）， 任何 .dh-btn 加 data-magnetic 就生效，不用逐页写。
