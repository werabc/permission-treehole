### 二、挖出并修复的真缺陷（本轮 9 个）

| 级别 | 缺陷 | 说明 |
|---|---|---|
| 🔴 | `SecurityConfig` 的 `/api/admin/**` 是 `hasAuthority('admin')` 全局硬门 | **这才是"只有 admin 能管树洞"的根因**：非 admin 角色在进方法级鉴权前就被 403。改为 `authenticated()`，权限交给 @PreAuthorize |
| 🔴 | 帖子详情 `authorName` 恒为 null | 详情接口直接用 `getById`，只手工处理匿名分支 → **详情页一直显示"未知用户"**，分类标签也不显示。改为走 `getPostDetail` 复用列表填充逻辑 |
| 🟠 | 评论只能点赞、无法取消 | 后端缺 `DELETE /comment/{id}/like`，前端只能本地加数 → 数字越点越多。已补端点 + Service |
| 🟠 | 前端从不调 `/post/{id}/liked` | 刷新后"已抱抱"状态丢失；此时点击走 likePost（服务端幂等直接返回）前端却仍 +1 → 计数漂移。已接入 |
| 🟠 | multipart 默认上限 1MB < 头像上限 2MB | 1~2MB 图片被容器拦成 **500**。补齐 `spring.servlet.multipart.max-file-size=10MB` + `MaxUploadSizeExceededException` 兜底成 400 |
| 🟠 | 图片 Content-Type 被追加 `;charset=UTF-8` | `server.servlet.encoding.force=true` 强制给所有响应加 charset。手写响应流 + `response.reset()` 解决 |
| 🟠 | 404 被伪装成 401 | `sendError` 触发 ERROR 派发到 `/error`，而 `/error` 未放行 → 匿名请求的错误状态被改写。放行 `/error` + 文件 404 改用 `setStatus` |
| 🟡 | `th_category.post_count` 从未维护 | 分类数字冻结，前端显式对不上（上一轮已修） |
| 🟡 | 演示数据依赖"库里恰好有人注册过" | e2e_demo_seed 只 UPDATE id=1/2 → 干净库下作者缺失。改为自带 demo_night/demo_deer 账号 |

### 五、踩坑（复用）
- **Java 注解顺序**：`@GetMapping` 在 `@PreAuthorize` **之前**。用脚本批量改权限码时若"往前找"，
  会命中上一个方法的注解 → 权限码整体错位一位。必须"从 mapping 往后找、到 public 前为止"
- **Spring Security + sendError**：`sendError(404)` 会内部转发到 `/error`，`/error` 未放行则最终返回 401
- **`server.servlet.encoding.force=true`** 会给所有响应（含图片）追加 `;charset=UTF-8`
- **Jackson `non_null`**：null 字段整个键都不出现，断言要用 `.get()` 读
- Git Bash 的 `mktemp -d` 生成 `/tmp/...`，curl `--data-binary @/tmp/...` 读不到文件（MSYS 路径转换）
  → 临时文件放项目内
- 浏览器测试的账号/通知断言不能依赖历史残留数据：th_user 无种子数据，**用户都由注册接口产生**；
  通知必须现场造（另一用户点赞我的帖子）
