## 推送代码上云（GitHub）

用户要求「git 上云，还是那个代理」。

### 代理结论（省事，记牢）
- 本机代理客户端是 **MyClash（Clash Plus，`D:\应用\Clash Plus\MyClash.exe`）**，走 **TUN 模式**：
  **没有任何本地 HTTP 代理端口在监听**（7877/7890/7897/10809/1080 全 closed），
  系统 WinINET 的 `ProxyEnable=0`（旧值 `127.0.0.1:7877` 已失效）。
- 因此 **git 不需要配 `http.proxy`** —— TUN 已透明接管流量。判断标准：
  `curl -m 8 -o /dev/null -w "%{http_code}" https://github.com` 直连返回 **200**。
- git 也**没有**任何 proxy 配置；`git ls-remote origin HEAD` 能直接成功即证明通路 OK。
- push 用 `credential.helper = !'E:\Git\gh.exe' auth git-credential`，非交互，不用输密码。

### ⚠️ 远端历史被换过 —— 关键坑
`git push` 首次被拒：`! [rejected] main -> main (fetch first)`。
拉取后发现 `+ 01227da...27cd1ec main -> origin/main (forced update)`：
- 本地 main 的**根提交**是 `01227da`「Initial commit: ...（Spring Boot 3.2 + Vue 3 RBAC + Novel）」
- 远端 main 变成了 `27cd1ec`，**消息/作者/日期完全相同但 tree 不同**，与本地**无共同祖先**（merge-base 为空）
- 远端那份是 145 文件的孤立快照（含 Novel 小说模块），本地 main 是 475 文件

**核查（决定强推是否安全的关键）**：
1. 远端 145 个文件，在本地 main 历史中的缺失数 = **0**（全部能找到）
2. Novel 模块本地在 `adb7557 feat: V2.0 系统全面升级` 中**主动删除**过
   → 远端只是本地历史的**落后快照**，强推零内容损失
3. 用 `git log main --format="%H %T" | grep <远端tree>` 匹配，命中 0 —— 确认它是独立快照

**处理方式（无损 + 可回溯）**：
1. 先把远端快照在本地和云端都存档：`git branch -f remote-main-backup 27cd1ec` + `git push origin remote-main-backup`
2. 再强推：`git push --force-with-lease=main:27cd1ec origin main` → `+ 27cd1ec...84616a4 main -> main (forced update)`

结果：云端 `main=84616a4`（与本地一致，61 个提交全部上去），`remote-main-backup=27cd1ec` 保留旧快照。
本地另有 `backup/agent-changes-20260922`（2d02e54）**未推送**。
