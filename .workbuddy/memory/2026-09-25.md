## 推送代码上云（GitHub）

用户要求「git 上云，还是那个代理」。

### 代理结论（省事，记牢）
- 本机代理客户端是 **MyClash（Clash Plus，`D:\应用\Clash Plus\MyClash.exe`）**，走 **TUN 模式**：
  **没有任何本地 HTTP 代理端口在监听**（7877/7890/7897/10809/1080 全 closed），
  系统 WinINET 的 `ProxyEnable=0`（旧值 `127.0.0.1:7877` 已失效）。
- 因此 **git 不需要配 `http.proxy`** —— TUN 已透明接管流量。判断标准：
  `curl -m 8 -o /dev/null -w "%{http_code}" https://github.com` 直连返回 **200**。
- git 也**没有**任何 proxy 配置；`git ls-remote origin HEAD` 能直接成功即证明通路 OK。
- push 用 `credential.helper = !'E:\Git\gh.exe' auth git-credential`，非交互，不用输密码。

### ⚠️ 远端历史被换过 —— 关键坑
`git push` 首次被拒：`! [rejected] main -> main (fetch first)`。
拉取后发现 `+ 01227da...27cd1ec main -> origin/main (forced update)`：
- 本地 main 的**根提交**是 `01227da`「Initial commit: ...（Spring Boot 3.2 + Vue 3 RBAC + Novel）」
- 远端 main 变成了 `27cd1ec`，**消息/作者/日期完全相同但 tree 不同**，与本地**无共同祖先**（merge-base 为空）
- 远端那份是 145 文件的孤立快照（含 Novel 小说模块），本地 main 是 475 文件

**核查（决定强推是否安全的关键）**：
1. 远端 145 个文件，在本地 main 历史中的缺失数 = **0**（全部能找到）
2. Novel 模块本地在 `adb7557 feat: V2.0 系统全面升级` 中**主动删除**过
   → 远端只是本地历史的**落后快照**，强推零内容损失
3. 用 `git log main --format="%H %T" | grep <远端tree>` 匹配，命中 0 —— 确认它是独立快照

**处理方式（无损 + 可回溯）**：
1. 先把远端快照在本地和云端都存档：`git branch -f remote-main-backup 27cd1ec` + `git push origin remote-main-backup`
2. 再强推：`git push --force-with-lease=main:27cd1ec origin main` → `+ 27cd1ec...84616a4 main -> main (forced update)`

结果：云端 `main=84616a4`（与本地一致，61 个提交全部上去），`remote-main-backup=27cd1ec` 保留旧快照。
本地另有 `backup/agent-changes-20260922`（2d02e54）**未推送**。

## 仓库归置：permission-admin → permission-treehole（改名 + 去重）

用户：「旧的那个不是还有小说模块吗？你给我安排一下，把提交搞好就行。」名字选 `permission-treehole`。

### 查清的三个事实
1. **`werabc/java-dev-toolkit` 和 `werabc/permission-admin` 是同一个项目** ——
   两边都有 `permission-admin/` + `permission-ui/` + `treehole-web/`。java-dev-toolkit 是 201 文件的旧版，
   且名字严重误导（叫 "java-dev-toolkit"、描述 "Java1树洞"，实际是完整的权限管理系统 + 树洞）。
2. **java-dev-toolkit 那 10 个"独有文件"全部是被 s1 有意淘汰的**，无保留价值：
   `TestController.java`（调试端点，`169a648` 清理）、`Welcome.vue`（`89cf7c0` 改版替换）、
   `auto-imports.d.ts` / `components.d.ts`（vite 生成物，从未提交）、两个 `application-*.yml`
   （改成 `config/` 方案）、`docs/API.md` / `DEVELOPMENT.md`（被 `接口文档.md` 取代）、`deploy.sh`/`README.md`。
3. **Novel（小说）模块一点没丢**：s1 自己的历史里 `adb7557^`（V2.0 全面升级之前）完整存着 **28 个 Novel 文件**，
   云端 `remote-main-backup` 分支也有 28 个。不需要为它保留旧仓库。

### 执行
```
gh repo rename permission-treehole --repo werabc/permission-admin --yes          # 主仓库
gh repo rename permission-treehole-archive --repo werabc/java-dev-toolkit --yes  # 旧版归档
git remote set-url origin https://github.com/werabc/permission-treehole.git
git push origin main                                                             # 84616a4..800f273
gh repo edit ... --description ...                                               # 两个描述都改成如实
```
选 `permission-admin` 作主仓库基座的原因：**只有它带着这个项目真实的 61 提交演进历史**；
把 s1 强推进 java-dev-toolkit 会丢掉它 206 条重写历史且毫无收益。

### ⚠️ 顺带发现的安全问题
`java-dev-toolkit` 的旧镜像里存着**真实明文凭据**（MySQL 密码 `123456abc`、真实 JWT 密钥），
远端后来已换成占位符（`your-db-password` / `dev-demo-jwt-secret-...`）。
所以删除该镜像同时消除了公开仓库里的一份明文密码副本。

### 沙箱限制（重要）
- `Add-Type`（加载 .NET 程序集）被安全策略拦截
- `New-Object -ComObject`（COM 实例化）被安全策略拦截
- ⇒ **回收站（Recycle Bin）在沙箱内不可用**，只能永久删除 → 必须向用户二次确认
- `Remove-Item -Recurse -Force` 会经沙箱 `safe-delete` 层；错误信息形如
  `[safe-delete][SAFE_DELETE_FAIL_CLOSED] {"reason":"trash-failed"}`，此时**删除其实已完成**，用 `Test-Path` 复核即可
- 已删除：`D:/audit-backup/{c1-blog,java-dev-toolkit}.git`。`D:/audit-backup/` 现仅剩 `permission-admin.git`
